# Yandex Relay — дизайн

Статус (2026-09-28): этап 1. Драйвер v0.1.6 проверен на объекте без HA (`docs/STAGE1-SITE-TEST.md`: комнаты, звук, панель, Pause/Stop через комнату, autobind). c4_relay v0.1.0 написан, 28 тестов на ядре HA 2026.2; установка — `docs/HA-INSTALL.md`, на живом HA ещё не проверен.

## 1. Цель

Пользователь говорит Яндекс Станции «Алиса, включи музыку». Станция начинает играть, а музыка звучит не из неё, а из мультирума Control4 в той комнате, где стоит станция. Разговоры с Алисой (погода, таймеры, ответы) ничего не запускают.

Дальше:
- в разных комнатах может одновременно играть разная музыка (у каждой станции своя комната);
- по команде музыку ведущей комнаты можно добавить в другие комнаты (нативная media session Control4, синхронно).

## 2. Принципы

- **Универсальность.** Ни в драйвере, ни в HA-интеграции нет ничего под конкретный объект: списков комнат, ID, имён станций. Всё обнаруживается автоматически или задаётся в UI.
- **Станция — мастер очереди.** Очередь, «Моя волна», next/prev ведёт станция через AlexxIT. Relay только играет URL, который ему прислали, и сам треки не переключает.
- **Control4 — источник правды по комнатам и сессиям.** HA — источник правды по станциям и привязке «станция → комната».
- **Только локальная сеть.** Облако Control4 не используется. Облако Яндекса используется только через AlexxIT.

## 3. Компоненты

```
Яндекс Станция ──Glagol (локально)──► HA: AlexxIT YandexStation     (готовое, не трогаем)
                                          │ source = "Control4 <комната>"
                                          ▼ media_player.play_media(url)
                                    HA: c4_relay                      (пишем: custom integration)
                                          │ HTTP JSON
                                          ▼
                                    Control4: Yandex Relay            (пишем: драйвер, 1 экземпляр на объект)
                                          │ SELECT_INTERNET_RADIO ROOM_ID=…
                                          ▼
                                    контроллер → зоны → колонки

Обратно: панель C4 (Next/Pause) → Relay → webhook HA → c4_relay → станция
```

### 3.1 AlexxIT YandexStation (готовое)

Что делает сам (проверено по `core/yandex_station.py`, `async_set_state` / `sync_play_media`):
- трансляция включается выбором `source` станции (всё, кроме «Станция»);
- на каждый новый `playerState.id` получает ссылку (`get_file_info(quality, codecs)`) и вызывает `media_player.play_media` на цели; URL — прокси HA `http://<HA_IP>:8123/api/yandex_station/<jwt>.<ext>`, JWT живёт 1 час, без авторизации;
- `playing` true/false → `media_play` / `media_pause` на цели;
- громкость станции → `volume_set` на цели (`sync_volume` отключает или пересчитывает);
- приглушает станцию, пока `aliceState == IDLE`, возвращает звук, когда с Алисой говорят;
- диалоги `playerState.id` не меняют, поэтому трансляцию не запускают.

### 3.2 Yandex Relay (драйвер Control4)

- `media_service` proxy, как в основном драйвере Yandex Music; рабочие куски берём оттуда (`SELECT_INTERNET_RADIO`, `UPDATE_MEDIA_INFO`, dashboard).
- **Один экземпляр на объект.** Состояние хранится по очередям `gQueues[queueId]` и комнатам `gRooms[roomId]`, как в TuneIn (`tunein_extracted/driver.lua`, `OnInternetRadioSelected`). Разные комнаты — разные очереди C4, играют одновременно.
- HTTP-сервер на `C4:CreateServer` (порт — свойство драйвера).
- Список комнат — `C4:GetProjectItems` (фильтр комнат), без ручной настройки. Комната в XML проекта — `<type>8</type>`; подтверждено на объекте 2026-09-28 (найдено 8 комнат).
- Сам треки не переключает: `QUEUE_STATE_CHANGED END` не вызывает next — это решает станция.

Свойства (Composer):
- `Bridge Port` — по умолчанию 18765;
- `Pairing Code` — read-only, генерируется при первом запуске; вводится в HA при добавлении интеграции;
- `Paired With` — read-only, адрес HA после сопряжения;
- `Debug Mode`, `Driver Version`.

Никаких комнат, URL HA и токенов HA в свойствах нет: адрес webhook HA передаёт при сопряжении.

### 3.3 c4_relay (HA custom integration)

- **Config flow:** host драйвера + Pairing Code → `GET /info` → `POST /pair` (передаёт webhook URL) → `GET /rooms`.
- **Привязка станций:** находит станции AlexxIT (entity registry, платформа `yandex_station`) и предлагает привязку «станция → комната C4» по area HA / совпадению имени (без учёта регистра и ё/е). Пользователь подтверждает или меняет. Options flow позволяет перепривязать и пересканировать комнаты.
- **Сущности:** `media_player` на каждую комнату C4, в том числе без станции (она нужна для объединения). Возможности: `PLAY_MEDIA | PLAY | PAUSE | STOP | NEXT_TRACK | PREVIOUS_TRACK | VOLUME_SET`, на этапе 3 добавится `GROUPING`.
- `play_media(url)` → `POST /play`. Метаданные (title, artist, обложка, длительность) берутся из атрибутов привязанной станции: AlexxIT передаёт их только Chromecast-целям.
- `next` / `prev` / `play` / `pause` → на станцию; transport-события из webhook → на станцию.
- **Самовосстановление источника:** если у привязанной станции `source` не равен её сущности c4_relay, интеграция выбирает его сама. Это покрывает рестарт HA (source не восстанавливается, проверено: `async_added_to_hass` восстанавливает только `sound_mode`) и переподключения станции.
- Переключатель на станцию «Трансляция в Control4» (switch): выкл = source «Станция».

## 3.4 Аудиотракт: источник звука — контроллер

Relay не выводит звук сам и ничего не знает о матрицах. Он делает `SELECT_INTERNET_RADIO {ROOM_ID, STATION_URL}`, как основной драйвер Yandex Music. Дальше работает цифровое аудио самого контроллера (Ryff): он скачивает файл, декодирует его и выдаёт на физический выход, а путь до зоны Control4 строит по соединениям из Composer (выход контроллера → вход матрицы → выход матрицы → комната). Поэтому один и тот же драйвер работает и с матрицей, и с сетевыми endpoint'ами: маршрутизация — забота Composer, а не кода.

**Сколько разных потоков одновременно.** Каждый независимый поток занимает отдельный физический выход контроллера:
- CORE 5 — 7 выходов (3 аналоговых, 3 коаксиальных, 1 HDMI), до 7 одновременных потоков;
- EA-5 — 5 выходов (2 аналоговых, 2 коаксиальных, 1 HDMI).

С матрицей реальный предел — **сколько выходов контроллера физически заведено в матрицу**. HDMI обычно туда не идёт, коаксиальные — только если у матрицы есть цифровые входы. Пример: CORE 5 и 3 аналоговых выхода в матрицу → до 3 комнат с разной музыкой одновременно.

**Одна музыка в нескольких комнатах** (этап 3) с матрицей получается бесплатно и идеально синхронно: сессия C4 занимает один выход контроллера, а матрица разводит этот вход на несколько зон. Сетевой задержки между комнатами нет — это один и тот же аналоговый сигнал.

**Если выходы кончились.** Как поведёт себя Control4, если нужен ещё один независимый поток, а свободного выхода в матрицу нет (откажет, займёт чужой выход, ошибка) — проверить на объекте. Возможная политика c4_relay на этом случае: не запускать новый поток, а присоединить комнату к уже играющей сессии и сообщить голосом.

**Настройка в Composer (делает интегратор, код не нужен):** выходы контроллера соединены со входами матрицы, выходы матрицы — с комнатами, Relay добавлен в проект. Это та же настройка, что уже нужна для основного драйвера Yandex Music и любых сервисов цифрового аудио.

**Откуда контроллер берёт файл.** AlexxIT отдаёт цели ссылку на свой прокси: `http://<HA>:8123/api/yandex_station/<jwt>.mp3`. В полезной нагрузке JWT лежит исходная прямая ссылка CDN Яндекса (`get-file-info`, `transports=raw`). JWT подписан HS256, но не зашифрован, поэтому c4_relay может её прочитать без ключа (проверено по `core/stream.py:get_url` и `core/yandex_music.py:get_file_info`). Поэтому в `/play` передаются обе ссылки:
- `url` — прямая ссылка CDN: контроллер качает сам, HA в звуковой цепочке не участвует, рестарт HA не обрывает текущий трек;
- `fallback_url` — прокси AlexxIT, если прямая не открылась.

Relay пробует `url`, при ошибке потока переключается на `fallback_url`. Разбор JWT зависит от внутреннего формата AlexxIT: если формат изменится, c4_relay просто не заполнит `url` и всё продолжит работать через прокси.

## 4. Протокол Relay ↔ HA

HTTP/1.1, JSON, заголовок `X-Relay-Key: <Pairing Code>` на каждом запросе к драйверу. У всех команд над комнатой есть `room_id`, даже на объекте с одной комнатой.

Драйвер (сервер):

| Метод | Путь | Тело / ответ |
|---|---|---|
| GET | `/info` | → `{driver, version, paired}` |
| POST | `/pair` | `{webhook_url}` → `{ok}`; хранится через `C4:PersistSetValue` |
| GET | `/rooms` | → `[{id, name}]` |
| POST | `/play` | `{room_id, url, fallback_url, title, artist, album, image, duration_ms, key}` (см. §3.4); `key` — ID трека, по нему отсекаются события предыдущего трека |
| POST | `/pause`, `/resume`, `/stop` | `{room_id}` |
| GET | `/state?room_id=` | → `{room_id, state, queue_id, title, artist, position_ms}` |
| POST | `/join`, `/leave` | этап 3: `{room_id, rooms: [...]}` |

HA (webhook, `POST <webhook_url>`), от драйвера:
- `{event: "transport", room_id, action: "next"|"prev"|"play"|"pause"|"stop"}` — кнопки панели;
- `{event: "state", room_id, state}` — изменение состояния очереди;
- `{event: "deselected", room_id}` — в комнате выбрали другой источник, станцию нужно поставить на паузу.

Секреты: Pairing Code защищает драйвер, секретный ID webhook защищает HA. Long-lived token HA в драйвере не нужен.

**Пауза и продолжение** (проверено на объекте 2026-09-28).
- Pause и Stop на панели — кнопки типа `ROOM` (как у TuneIn): с типом `PROTOCOL` нажатие доходило только до драйвера. Уведомление комнаты `PAUSE|STOP {ROOM_ID}` драйвер пересылает в HA.
- **Пауза цифрового аудио звук не глушит**: на потоке интернет-радио `PAUSE` меняет только состояние очереди (`STATE=PAUSE`), комната продолжает звучать. Поэтому любая пауза и стоп — из HA (`/pause`, `/stop`, «Алиса, пауза/стоп/выключи») и с панели — **выключают комнату** (`C4:SendToDevice(room, "ROOM_OFF")`). Последующий `OFF {}` без ID комнаты драйвер узнаёт как свой и эхом в HA не шлёт.
- После выключения очередь удалена, поэтому Play/`/resume` **перезапускают трек** с начала (`resume: restart`), и c4_relay перематывает станцию на 0. Ветка `in_place` (команда комнаты `PLAY`) остаётся для очереди, которая стоит в `PAUSE` по чужой команде.

**Состояния комнаты** в событии `state`: `starting`, `playing`, `paused`, `stopped`, `ended`. `ended` — трек доиграл сам; драйвер ничего не запускает, следующий трек пришлёт станция.

## 5. Поток «Алиса, включи музыку»

1. Станция отвечает голосом и начинает трек; AlexxIT глушит её, когда `aliceState` становится `IDLE`.
2. AlexxIT: новый `playerState.id` → `play_media(url)` на `media_player.c4_relay_<комната>`.
3. c4_relay: берёт метаданные станции → `POST /play`.
4. Relay: `SELECT_INTERNET_RADIO {ROOM_ID, STATION_URL}` → C4 включает комнату, контроллер тянет файл с CDN Яндекса (или с прокси HA, §3.4) и выдаёт звук на свой выход → матрица → зона.
5. `INTERNET_RADIO_SELECTED` / `QUEUE_STATE_CHANGED` → Relay запоминает `queueId ↔ roomId` и отдаёт `UPDATE_MEDIA_INFO` на панели.

Ожидаемая задержка 2–4 с; на границе треков пауза 1–3 с.

## 6. Поведение по сценариям

- «Алиса, какая погода» во время музыки — трансляция не меняется; c4_relay приглушает комнату, пока `alice_state != IDLE` (этап 2).
- «Алиса, дальше/пауза/продолжи/стоп» — через AlexxIT → c4_relay → Relay.
- «Алиса, громче» — `volume_set` → громкость C4 **только этой комнаты**, с потолком на комнату. Потолок обязателен: при включении трансляции AlexxIT сразу шлёт текущую громкость станции.
- Next/Pause на панели C4 → webhook → станция → обратно вниз.
- На C4 выбрали другой источник → `deselected` → пауза станции (иначе она продолжит играть без звука).
- Будильник с музыкой тоже запустит трансляцию → на этапе 4 тихие часы / игнор, если комната выключена.
- Пауза дольше N минут → комната выключается (этап 4).

## 7. Объединение комнат (этап 3)

- Нативные media sessions Control4 («Digital Media → Add Rooms»). Не второй поток: он даст рассинхрон и эхо.
- Ведущая комната — та, чья станция играет; управляет её станция и панели любой комнаты сессии (команды приходят в Relay ведущей очереди).
- Станция присоединённой комнаты запускает свою музыку → её `SELECT_INTERNET_RADIO` сам выводит комнату из чужой сессии.
- Команды: HA `media_player.join` / `unjoin` (GROUPING); голос — сценарии Яндекса («Фраза» → «Любое умное устройство»), событие `yandex_scenario` (`entity_id` = откуда, `scenario_name` = какая команда); нативное добавление комнат в Navigator.
- Встроенный мультирум Яндекса: если ведомая станция приносит тот же трек, что играет ведущая сессия, присоединяем комнату, а не запускаем второй поток. Это эвристика, проверить.
- **Неизвестное:** низкоуровневая команда «Add Rooms» для вызова из Lua. План: тестовый скрипт в Composer → экспорт `.c4p` → прочитать команду и параметры в XML программирования. Запасной вариант: события драйвера и программирование в Composer.

## 8. Известные риски

- `sync_sources` у AlexxIT инициализируется один раз (`init_local_mode`). Если сущности c4_relay появятся позже, станция их не увидит. План: после создания сущностей c4_relay перезагружает config entry `yandex_station`. Проверить на этапе 1, запасной вариант — YAML `yandex_station: media_players:` с `speaker_id`.
- Для `fallback_url` контроллер должен ходить в HA по HTTP и IP. «URL для домашней сети» в HA = `http://<IP>:8123`.
- С матрицей число одновременных разных потоков ограничено выходами контроллера, заведёнными в матрицу (§3.4).
- Кодек: AlexxIT по умолчанию `codecs: mp3` (при `lossless` это 320 kbps). Control4 mp3 гарантированно играет; flac-mp4 / aac-mp4 не проверены.
- Glagol и прокси AlexxIT — неофициальные API.
- В присоединённой комнате встроенный «Алиса, стоп» ничего не сделает (там станция не играет) — нужна отдельная фраза-сценарий.

## 9. Этапы

**Этап 1 — объект с одной комнатой.**
- Relay: HTTP-сервер, `/info`, `/pair`, `/rooms`, `/play`, `/pause`, `/resume`, `/stop`, `/state`; очереди по `queueId`; now playing; webhook transport.
- c4_relay: config flow, привязка, сущность на комнату, play_media → Relay, transport → станция, самовосстановление source, перезагрузка AlexxIT.
- Приёмка:
  1. «Алиса, включи музыку» → играет C4 в комнате ≤ 5 с, на панели название, артист, обложка.
  2. «Алиса, какая погода» → в C4 ничего не меняется.
  3. «Алиса, дальше / пауза / продолжи» → C4 следует.
  4. Next / Pause на панели C4 → станция следует.
  5. Рестарт HA → работает без ручных действий.
  6. Перезагрузка контроллера → сервер Relay поднимается, HA восстанавливает связь.
  7. В комнате выбрали другой источник → станция на паузе.

**Этап 2** — громкость с потолком, приглушение по `alice_state`, несколько комнат с разной музыкой одновременно.
**Этап 3** — объединение комнат.
**Этап 4** — эвристика мультирума Яндекса, будильники / тихие часы, автовыключение.
